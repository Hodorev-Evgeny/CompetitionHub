## Идея проекта

**CompetitionHub** — учебный многостраничный сайт, на котором можно находить соревнования по спорту, киберспорту, интеллектуальным играм и творчеству, просматривать информацию, записываться на участие и создавать свои соревнования. В отличие от интернет-магазина, здесь нет продаж, корзины и оплаты — основная пользовательская задача связана с участием в событиях.

> **Согласование темы.** В методических указаниях к КР №2 предписано сохранить предметную область предыдущей КР №1 — интернет-магазин либо каталог услуг. CompetitionHub — другая предметная область; **её необходимо согласовать с преподавателем**, чтобы формально удовлетворить этому пункту задания. Все интерфейсные требования КР №2 в этом проекте реализованы.

## Технологии

- HTML5: семантические элементы `header`/`nav`/`main`/`section`/`article`/`aside`/`footer`, формы с `label`, `required`, `minlength`, `input type`.
- CSS3: небольшие дополнительные стили, анимации при наведении, адаптивные медиазапросы.
- **Bootstrap 5.3.6** (локально): сетка, utility-классы, готовые компоненты и Bootstrap JS Bundle. Методичка показывает 5.3.8, но используется совместимая версия **5.3.6** той же ветки 5.3.x.
- JavaScript: DOM, обработчики событий, динамический вывод карточек, проверка полей, `localStorage`.
- Git/GitHub: проект предназначен для размещения в **отдельном репозитории** и работы через ветки и Pull Request.

Фреймворк подключён в HTML в следующем порядке: сначала `vendor/bootstrap/css/bootstrap.min.css`, затем `css/custom.css`. Для модальных окон, tabs, accordion и мобильной навигации подключён `vendor/bootstrap/js/bootstrap.bundle.min.js`.

## Демонстрация работоспособности

1. Открыть `catalog.html` — посмотреть 8 демонстрационных соревнований.
2. Выбрать категорию «Киберспорт» или ввести название в поиск — сетка карточек должна обновиться.
3. Открыть соревнование с открытой регистрацией и нажать **«Подать заявку»** — появится Bootstrap `modal`.
4. Заполнить имя, e-mail, согласие — заявка сохранится и появится уведомление `toast`.
5. Перейти в `profile.html` → **«Мои заявки»** — заявка отобразится (без настроенного профиля видны все локальные заявки).
6. Открыть `create.html`, заполнить обязательные поля — будет создано новое соревнование, оно появится в `catalog.html` и профиле.
7. Открыть `bracket.html` и выбрать соревнование — отобразятся три этапа турнирной сетки.
8. Открыть `rating.html` и отфильтровать участников по категории.
9. Открыть `auth.html` и указать имя/e-mail — информация появится в `profile.html`. Это демонстрационный профиль без пароля.
10. В DevTools проверить ширины **375, 768, 1024, 1440 px**, мобильное меню, форму, модальное окно и таблицы.

## Ограничения учебной реализации

В практической работе №10 **не требуется backend**, поэтому:

- регистрация, вход, создание и запись на события демонстрационные — нет серверных аккаунтов, отправки писем и синхронизации между пользователями;
- `localStorage` не подходит для настоящего защищённого хранения пользовательских данных; **не используйте реальные персональные данные** в демо;
- турнирная сетка и таблица лидеров отображают учебный пример, но не рассчитывают победителей по реальным матчам;
- для полноценного сервиса в будущем нужны сервер, база данных, реальные аккаунты и API.
